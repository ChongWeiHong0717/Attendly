# Previous planning Excel Import Plan

V1 is deliberately structured so yearly Excel rollover can be added without changing the core student identity model.

## Recommended export/import columns

| Student ID | Student Name | IC / MyKid | Class |
|---|---|---|---|
| ST000001 | Ali Ahmad | optional | 2 Bestari |
| ST000002 | Ali Ahmad | optional | 2 Cempaka |

Rules:

1. **Student ID is the primary identity.** It is permanent and never reused.
2. Existing rows with a Student ID update only that student's enrollment for the active academic year.
3. **Names are never used for deduplication.** Two identical names may be two different students.
4. IC/MyKid is only a secondary/backup identifier.
5. A genuinely new student with a blank Student ID gets a newly generated permanent Student ID.
6. The importer should show a preview and validation errors before committing anything.
7. Unknown class names should be flagged for admin review rather than silently creating or guessing a class.
8. Import should run in a transaction so a failed import does not leave a half-finished academic year.

## Year rollover flow

1. Admin closes the current year and creates the next academic year.
2. Existing student records and old enrollments remain untouched.
3. The new year initially has no student enrollments and no teacher-class assignments.
4. Admin imports the new Excel mapping.
5. Existing Student IDs are assigned to their new classes for that year.
6. Admin assigns teachers to their new classes.

This design supports movement such as `1 Aranda -> 2 Bestari` without assuming any fixed promotion path.
